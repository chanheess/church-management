# OCI 무료 플랜 기반 운영 전환 계획

## Summary

현재 로컬 데스크톱형 Spring 앱을 OCI 무료 VM + PostgreSQL 기반의 서버형 서비스로 전환한다.
데이터 원본은 당분간 엑셀 유지로 고정하고, DB는 계정/권한/감사로그/설정값/출력 작업/엑셀 버전 메타데이터 저장용으로 사용한다.
자동 출력은 Oracle 서버가 직접 프린터를 제어하는 대신, HP ePrint/클라우드 인쇄 경로를 표준으로 삼아 서버가 PDF를 생성하고 승인된 프린터 주소로 전송하는
구조로 설계한다.

## Key Changes

### 1. 서버 운영 구조

- OCI Always Free Ubuntu VM 1대에 애플리케이션과 PostgreSQL을 함께 운영한다.
- 배포 방식은 Docker Compose로 고정한다.
- 구성은 spring-app + postgres + reverse proxy(nginx 또는 caddy 중 caddy 선택)로 단순화한다.
- 앱은 서버 프로필에서 반드시 headless로 동작하게 바꾸고, 현재의 브라우저 자동 실행/시스템 트레이 초기화는 서버 프로필에서 비활성화한다.
- 외부 노출은 443만 허용하고, 관리 화면은 애플리케이션 로그인 없이는 접근 불가로 둔다.

### 2. 데이터 구조와 엑셀 유지 전략

- 회원/출석/주보 기초 데이터의 원본은 계속 엑셀로 유지한다.
- 서버에는 “활성 엑셀 파일” 1개만 두고, 업로드 시 이전 파일은 백업 디렉터리로 버전 보관한다.
- 앱 내부에는 ExcelDataSource 계층을 두고, 화면/주보/출석/대표기도 기능은 이 계층만 통해 데이터를 읽게 한다.
- 관리자 화면에서 엑셀 업로드, 활성 버전 확인, 최근 동기화 시각, 파싱 오류 확인이 가능해야 한다.
- 이슈 8 대비를 위해 앱 내 수정 기능은 직접 셀 수정 후 저장하는 방식으로 설계한다.
- DB에는 엑셀 원본 데이터 전체를 정규 저장하지 않고, 파일 경로/버전/해시/업로드자/업로드시각/파싱상태만 저장한다.

### 3. 운영 DB 역할

- PostgreSQL에는 아래만 저장한다.
- 관리자 계정, 비밀번호 해시, 권한, 마지막 로그인, 실패 횟수
- 가입 요청, 허용 IP 정책, 계정 승인 이력
- 텍스트 설정값, 경로 설정값, 프린트 설정값
- 출력 작업 큐, 출력 결과, 재시도 횟수, 감사 로그
- 향후 DB 전환을 대비해 member_snapshot 같은 읽기 전용 캐시 테이블은 선택적으로 두되, 1차 구현 범위에서는 필수로 두지 않는다.

### 4. 인증/보안

- Spring Security를 도입해 관리자 로그인 체계를 추가한다.
- 가입은 허용 IP 대역에서만 가능하게 하고, 가입 후에도 관리자가 승인해야 로그인 가능하게 한다.
- 로그인은 이메일 + 강한 비밀번호 + 이메일 인증 기반 신뢰기기 방식으로 설계한다.
- 관리자 계정 관련 모든 이벤트는 감사 로그에 남긴다.
- 관리자 기능은 일반 조회와 분리한다. 공개 화면이 필요 없으면 전체 앱을 인증 뒤 접근 구조로 둔다.
- 비밀값은 .env가 아니라 OCI 서버 환경변수 또는 Compose secret 파일로 관리한다.
- 프린터 대상은 HP ePrint 주소 화이트리스트로 제한하고, 임의 이메일 주소로 출력 요청은 불가하게 한다.

### 5. 자동 출력 설계

- 서버는 인쇄 시점에 HTML 화면을 직접 프린트하지 않고, 주보/출석표를 PDF로 렌더링한 뒤 HP ePrint 주소로 전송한다.
- 출력 흐름은 스케줄 생성 -> 렌더링 -> 페이지 수 검증 -> 메일 발송 -> 결과 기록으로 고정한다.
- 출력 작업은 수동 실행과 예약 실행을 모두 지원한다.
- 예약은 DB 기반 스케줄 테이블을 두고 앱 내 스케줄러가 분 단위로 확인한다.
- 실패 시 재시도 정책은 최대 3회, 지수 백오프로 고정한다.
- “몇 장 출력 가능한지” 요구는 렌더링 후 PDF 페이지 수 계산으로 처리한다.
- “프린트 가능한 상황인지”는 프린터 설정 활성화 여부, SMTP 연결, 템플릿 렌더 성공, 첨부 크기 제한, 대상 주소 화이트리스트 통과 여부로 판정한다.

## Public Interfaces

- /admin/login, /admin/logout, /admin/users, /admin/signup-requests
- /admin/config/paths, /admin/config/text, /admin/config/print
- /admin/data/excel/upload, /admin/data/excel/status, /admin/data/excel/history
- /admin/print-jobs, /admin/print-jobs/{id}/run, /admin/print-schedules
- 기존 /bulletin, /attendance, /representative-prayer는 유지하되, 내부 데이터 접근은 파일 직접 참조 대신 데이터소스 계층을 사용하도록 변경
- 서버 설정 프로필 분리:
    - local: 현재처럼 로컬 작업용
    - server: headless, 인증 사용, OCI 운영용

## Delivery Phases

### Phase 1. 서버/보안/데이터 기초

- OCI VM, 도메인, HTTPS, Compose 배포
- 서버 프로필 분리와 로컬 UI 코드 비활성화
- PostgreSQL 연결
- 관리자 인증, 허용 IP 가입, 승인 플로우, 감사 로그
- 엑셀 업로드/버전관리/파싱 상태 화면
- 기존 주보/출석/대표기도 기능이 서버 업로드 엑셀 기준으로 정상 동작하도록 이행

### Phase 2. 자동화 기능

- PDF 렌더링 파이프라인 추가
- HP ePrint SMTP 전송 추가
- 출력 작업 큐와 예약 실행
- 출력 가능 여부 점검, 페이지 수 계산, 실패 재시도
- 이후 이슈 8의 “화면 수정 -> 엑셀 반영” 기능 구현

## Test Plan

- 서버 프로필에서 브라우저/트레이 초기화 없이 정상 기동
- 엑셀 업로드 후 주보/출석/대표기도 화면이 기존과 동일하게 생성
- 잘못된 엑셀 업로드 시 파싱 오류가 사용자에게 노출되고 기존 활성 버전은 유지
- 허용되지 않은 IP에서는 가입 요청 차단
- 승인되지 않은 계정 로그인 차단
- 비밀번호 오류 누적, 이메일 인증 실패/만료, 신뢰기기 만료, 세션 만료 동작 확인
- 수동 출력 실행 시 PDF 생성, 페이지 수 기록, 메일 전송, 성공 로그 저장
- 예약 출력 시 지정 시각에 한 번만 실행되고 중복 실행 방지
- SMTP 실패, ePrint 주소 오류, 렌더 실패 시 재시도 후 최종 실패 기록
- 기존 로컬 개발 모드가 깨지지 않고 local 프로필에서 계속 사용 가능

## Assumptions

- Oracle 사용 의미는 OCI 무료 VM 인프라이며, DB 엔진은 구현 난이도와 운영 단순성을 위해 VM 내부 PostgreSQL로 고정한다.
- 데이터 원본은 당분간 엑셀이며, DB는 운영 메타데이터 저장소 역할만 수행한다.
- 자동 출력 경로는 HP ePrint/이메일 기반 클라우드 인쇄를 기본 전제로 한다.
- 관리자 보안은 지정 IP 회원가입 + 강한 비밀번호 + 이메일 인증 기반 신뢰기기 조합으로 설계한다.
- 이번 계획에서는 회원 원본 데이터를 Oracle DB로 완전 이관하지 않는다. 그 전환은 엑셀 write-back 운영이 안정화된 뒤 별도 단계로 다룬다.
