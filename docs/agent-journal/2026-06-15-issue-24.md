**날짜:** 2026-06-15

### 1. 문제 분석

- **요구사항:** 엑셀에서 불러온 값(성도 명단 / 셀 출석)을 저장할 JPA 엔티티 구조를 설계·구현한다. 엑셀 로딩 로직(#21~#23)이 아니라 "담을 그릇"인 엔티티/스키마에 집중한다.
- **현재 코드 상태:**
  - DB 없음. `build.gradle`에 JPA·DB 의존성 전무(POI·thymeleaf·webmvc·lombok·dotenv만).
  - 엑셀 파싱 결과는 POJO로 표현됨:
    - `model/Person`: name, positions(직분 다중), group(목장), cell(셀), birthday(MM-dd), status
    - `model/CellGroup`: cellName, attendanceMonth, members(List<AttendanceMember>), sundayDates(해당 월 일요일들)
    - `model/AttendanceMember`: name, birthday, phone, action(행삶), training(양육), attendance(출석현황), position
  - feature/03(미머지)이 별도로 JPA·security를 추가함 → 의존성 중복 조율 필요.
- **핵심 제약:**
  - 엑셀이 원본(source of truth). DB는 **단방향 읽기전용 스냅샷 캐시**(계획서: 회원 원본 DB 완전이관 아님).
  - 이 이슈는 스키마만. 매퍼/로딩/화면연동은 비범위.

### 2. 검토한 접근 방법

| 방법 | 장점 | 단점 | 채택 |
|------|------|------|------|
| A. POJO를 그대로 @Entity로 (단일 평면 테이블) | 가장 단순 | 직분 다중·출석 다중을 한 행에 못 담음, 정규화 0 | ✗ |
| B. Member + MonthlyAttendance + AttendanceMark 3계층 정규화 | 직분/월/주일 다중을 자연 표현, 조회 유연 | 테이블 3개+컬렉션 | ✓ |
| C. 완전 정규화(목장/셀/직분 마스터 테이블 분리) | 이론상 깔끔 | 스냅샷 캐시엔 과설계, 엑셀 원본과 괴리 | ✗ |

### 3. 결정 및 근거

채택: **방법 B**

- `Member`(성도) — 정체성: rosterYear, name, groupName(목장), cellName(셀), birthday, phone, status, positions(직분 `@ElementCollection`)
- `MonthlyAttendance`(월 출석) — member FK, year, month, cellName, action(행삶), training(양육)
- `AttendanceMark`(주일별 표시) — monthlyAttendance FK, sundayLabel(예 "7일"), mark(표시값)
- 각 엔티티 Spring Data JPA Repository.
- 패키지 분리: 엑셀-뷰 POJO(`model`)와 JPA 엔티티(`data.entity`)를 섞지 않음 → `com.saeanyang.management.data.entity` / `data.repository`.
- Lombok은 엔티티에 `@Data` 대신 `@Getter @Setter @NoArgsConstructor`만(컬렉션 equals/hashCode 함정 회피).
- DB: `spring-boot-starter-data-jpa` + H2(in-memory) — 로컬/테스트용. 서버 PostgreSQL은 후속.

근거: 스냅샷 캐시지만 직분(다중)·월별 출석·주일별 표시는 1:N이라 평면 테이블론 무리. 3계층이 엑셀 구조(명단 + 월별 셀 출석표)와 가장 자연스럽게 대응한다. 과한 마스터 분리는 읽기전용 캐시 목적에 비용만 늘린다.

### 7. 설계 변경 (2026-06-15, 사용자 피드백)

초기 3계층(Member + MonthlyAttendance + AttendanceMark)을 **단일 `Member`로 평면화**했다.

**근거:** 규모가 최대 ~100명(현재 ~50명)으로 매우 작고, 출석 표시는 조회 시 값만 가져와 그리므로 별도 출석 엔티티가 과설계다.

| 변경 | 내용 |
|------|------|
| 삭제 | `MonthlyAttendance`, `AttendanceMark` + 각 Repository — 값만 불러와 그리므로 불필요 |
| 흡수 | 행삶(`action`)·양육(`training`)만 `Member`로 이동 |
| 생일 | `String birthday`(MM-dd) → **`LocalDate birthDate`(생년월일)**. 엑셀 `19961013` 파싱, **연도 비면 현재 연도**(매퍼 책임) |
| 직분 | `Set<String>` → **`enum Position`**(STAFF/SHEPHERD/LEADER/INTERN/MEMBER, 한글 라벨 + `fromLabel`) |
| 연락처 | `String phone` 유지 — **숫자만 허용**(setter 검증, 숫자 외 문자 시 `IllegalArgumentException`). 하이픈 등 서식은 매퍼가 제거. PII라 추후 암호화 컨버터 여지 |

**자료형 결정 — 생년월일은 `LocalDate` 유지(String 아님):** PII 여부와 자료형은 별개다. 생년월일은 진짜 날짜(비교·나이·생일 추출·유효성)이므로 `LocalDate`가 맞고, PII 보호는 암호화 컨버터(타입 무관)로 처리한다. 연락처가 String인 이유는 PII가 아니라 "수량이 아닌 숫자 식별자(앞자리 0 보존)"이기 때문.

**범주형 필드 enum화 (사용자 피드백):** 문자열 범주값을 enum으로 바꿔 오타·미정의 값을 차단. "없음(default)"은 별도 값을 두지 않고 null/빈 집합으로 표현(대부분이 default라 저장·조회가 단순). 모든 enum은 `fromLabel(String) -> Optional`로 한글 라벨 매핑(미상은 빈 Optional).

| 필드 | enum | "없음" 표현 |
|------|------|-------------|
| 직분 `positions` | `Position`(간사/목자/리더/인턴) | **성도 = 빈 집합** (enum에서 성도 제외) |
| 상태 `status` | `MemberStatus`(해외/장결자/군대) | **정상 = null** |
| 행삶 `action`·양육 `training` | `ProgressStatus`(미진행/진행중/완료) | 미상 = null |

**패키지 구성 — 도메인별:** 기술 타입(entity/enums) 대신 도메인으로 묶는다. 현재는 member 도메인뿐이라 `data.member`(엔티티·리포지토리) + `data.member.enums`(enum). 향후 attendance·representative-prayer 데이터도 `data.<도메인>`으로 동일 패턴. (`enum`은 예약어라 폴더명은 `enums`)

**남은 결정:** 생년월일 파싱(연도 보정) 로직은 엑셀→엔티티 매퍼(#21~#23)에 구현. 로그인 ID는 `Member`가 아닌 `account.User`(feature/03)에 두고, 연결이 필요해지면 스냅샷 id가 아닌 안정 키로 소프트 링크.
