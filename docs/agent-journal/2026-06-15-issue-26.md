**날짜:** 2026-06-15

### 1. 문제 분석

- **요구사항:** 커밋 시점에 비밀값(시크릿) 유출을 자동 차단. 사용자 우려 = "확인 안 하고 commit하는 게 보안상 별로".
- **현재 상태:** `.githooks/pre-commit`은 `compileJava` + `test`만. 시크릿 검사 없음. `.gitignore`는 `.env`만 차단 → 코드/yml/픽스처에 들어간 비밀값은 무방비.
- **핵심 제약:**
  - 사람 리뷰는 PR이 적합(독립성·판단). commit 시점엔 **기계가 판단 가능한 자동 검사**가 맞음 → 시크릿 스캔.
  - 오탐(false positive)이 많으면 훅이 무력화됨 → 고신뢰 패턴 위주 + 플레이스홀더 제외 필수.
  - 코드베이스에 `password`/`secret` **이름**(PasswordPolicyService 등), `${MAIL_PASSWORD:}` **환경 플레이스홀더**가 존재 → 이런 건 절대 오탐하면 안 됨.

### 3. 결정 및 근거

채택: **방법 A — 내장 정규식 스캔**

- 별도 스크립트 `.githooks/secret-scan.sh` 작성 → pre-commit 맨 앞에서 호출(빠르니 컴파일 전에 fail-fast). CI에서도 재사용 가능.
- **스테이지된 추가 라인만**(`git diff --cached -U0` 의 `+` 라인) 스캔 → 기존 코드 오탐 방지.
- 고신뢰 패턴: PEM 개인키, AWS `AKIA`, GitHub `gh[pousr]_`, Slack `xox[baprs]-`, Google `AIza`, 서비스계정 `"private_key"`.
- 일반 패턴(시크릿명+따옴표 리터럴)은 **보수적으로**: `${`(환경변수)·빈 값·`your-/example/changeme/xxx/****` 플레이스홀더 제외.
- 발견 시 파일·라인·패턴을 출력하고 **exit 1**(커밋 차단). 긴급 우회는 `git commit --no-verify`(의도적 예외만).
- gitleaks는 향후 업그레이드 옵션으로 기록.

근거: 외부 설치 없이 모든 환경(로컬·서버·CI)에서 동작하고, 진짜 위험(개인키·클라우드키·토큰)을 높은 신뢰도로 잡는다. 오탐은 훅 무력화로 직결되므로 추가 라인 한정 + 플레이스홀더 제외로 억제.
