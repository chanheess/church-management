### 1. 문제 분석

- **요구사항:** Google Drive의 `.xlsx`를 읽기 전용으로 주기 동기화하고, 변경된 경우에만 활성 엑셀을 갱신한다.
- **현재 코드 상태:** #22에서 모든 엑셀 소비자가 `ExcelDataSource`를 사용하며 기본 구현은 로컬 파일뿐이다.
- **핵심 제약:** Drive 장애나 잘못된 다운로드가 서버 기동과 마지막 정상 스냅샷 사용을 막아서는 안 되며, 서비스계정 비밀은 환경변수로 받은 파일 경로에서만 읽어야 한다.

### 2. 검토한 접근 방법

| 방법 | 장점 | 단점 | 채택 여부 |
|---|---|---|---|
| Google Drive 전체 Java SDK 사용 | API 모델과 요청 코드가 제공됨 | 단일 파일 조회·다운로드에 의존성과 코드가 큼 | ✗ |
| 서비스계정 JWT까지 직접 구현 | 외부 의존성 없음 | 인증·토큰 갱신 보안 코드를 직접 유지해야 함 | ✗ |
| 공식 인증 라이브러리 + JDK HTTP로 Drive REST 호출 | 인증은 검증된 구현을 쓰고 Drive 호출은 두 개로 제한 | REST 응답 파싱과 상태 검사 필요 | ✓ |

### 3. 결정 및 근거

채택: **공식 Google 인증 + 로컬 마지막 정상 캐시**

- `EXCEL_SOURCE=google-drive`일 때만 Drive 구현체와 API 클라이언트를 생성한다. 기본값은 기존 로컬 구현이다.
- 원격 `version`이 저장된 버전과 다를 때만 다운로드한다.
- 다운로드 파일을 POI로 먼저 열어 검증한 뒤 같은 디렉터리의 캐시로 원자 교체한다.
- 동기화 실패는 경고만 남기고 기존 캐시를 유지한다. 캐시도 없을 때 실제 읽기 요청이 명시적인 오류를 받는다.
- 주기 동기화 외에 인증된 `POST /api/excel/sync`를 제공한다.
