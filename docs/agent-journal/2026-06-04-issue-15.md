# 에이전트 결정 로그

## 이슈 #15 — [workflow] 머지 후 워크트리 자동 닫기 및 이슈 제목 규칙 추가

**날짜:** 2026-06-04  
**브랜치:** feature/15 (feature/13 기반)  
**작업자:** Claude (claude-sonnet-4-6)

---

### 1. 문제 분석

- **요구사항 1:** PR 머지 후 워크트리를 수동으로 닫아야 하는 번거로움 → `post-merge` 훅으로 자동화
- **요구사항 2:** 이슈 제목 규칙 `[도메인] 작업 내용` 형식을 템플릿과 CLAUDE.md에 반영
- **현재 코드 상태:** `worktree-close.sh`에 PR OPEN 여부를 묻는 대화형 프롬프트가 있어 자동 실행 불가
- **핵심 제약:** 대화형 프롬프트를 완전히 제거하지 않고, 수동 실행 시는 기존 동작을 유지해야 함

---

### 2. 검토한 접근 방법

| 방법 | 장점 | 단점 | 채택 여부 |
|------|------|------|----------|
| `worktree-close.sh` 프롬프트 완전 제거 | 단순 | 수동 실행 시 안전망 사라짐 | ✗ |
| `--auto` 플래그로 분기 | 수동/자동 모두 지원 | 플래그 추가 | ✓ |
| 별도 auto-close 스크립트 작성 | 기존 스크립트 불변 | 중복 코드 | ✗ |

---

### 3. 결정 및 근거

채택: **`--auto` 플래그 방식**  
이유: 수동 실행 시 PR OPEN 경고는 유용한 안전망이므로 유지. `post-merge` 훅은 이미 브랜치가 머지됐음을 `merge-base`로 검증한 뒤 호출하므로 이중 확인 불필요.

`post-merge` 훅 동작 조건:
1. 현재 브랜치가 `main`일 때만 실행
2. `git merge-base --is-ancestor origin/<branch> origin/main`으로 머지 여부 검증
3. 해당하는 워크트리에만 `worktree-close.sh --auto` 호출
